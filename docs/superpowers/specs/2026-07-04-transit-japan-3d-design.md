# transit-japan-3d 設計書

日付: 2026-07-04 / ステータス: 承認済み

## 概要

日本列島のすべての公共交通機関(鉄道・バス・航空・船・ロープウェイ/ケーブルカー等)を
3Dマップでウェブ可視化するプロジェクト。商業化予定なし(個人利用・研究目的)。
モバイル端末とPCの両方で閲覧できるウェブアプリとして提供する。

主な体験:

1. **全国俯瞰モード** — 全交通モードの路線網を3D地図上にモード別色分けで俯瞰する
2. **車両アニメーション** — ズームインするとGTFS時刻表から補間した車両が
   現在時刻に合わせて動く(Mini Tokyo 3D方式のシミュレーション)
3. **時代スライダー** — 過去へ戻すと当時の路線網(廃線を含む)に切り替わる
4. **API連携** — api.transit.ls8h.com による発車標・経路検索・3D建物シーン

## ユーザーストーリー

- 地図を回転・傾斜させ、日本全体の交通網を俯瞰したい(PC/モバイル)
- モード(鉄道/バス/船/空路/索道)ごとにレイヤーをON/OFFしたい
- 都市部にズームして、いま走っている電車・バスがアニメーションで見たい
- 駅・停留所をタップして発車時刻・路線情報を見たい
- 時代スライダーを1960年に戻し、廃止された路線網を見たい

## アーキテクチャ

```
transit-japan-3d/
├── pipeline/          # データ収集・変換(Node.js/TypeScript + 一部Python)
│   ├── sources/       # ソース別ダウンローダ(再実行可能・キャッシュ付き)
│   └── build/         # 正規化 → GeoJSON → PMTiles / 時刻表DB化
├── data/
│   ├── raw/           # ダウンロード生データ(git管理外)
│   └── dist/          # 生成物: PMTiles, GeoJSON, 時刻表JSON(git管理外・再生成可能)
└── web/               # Vite + TypeScript + deck.gl + MapLibre GL JS
    ├── src/layers/    # モード別deck.glレイヤー
    ├── src/anim/      # 時刻表補間による車両アニメーション
    ├── src/timeline/  # 時代スライダー(歴史モード)
    └── src/api/       # transit.ls8h.com クライアント(openapi-typescript生成)
```

- **配信はサーバレス静的構成**: PMTiles + 静的JSONをHTTP Range取得。
  ローカル開発は `vite dev`、公開は任意の静的ホスティングで可。
- パイプラインは冪等・再実行可能。ソース更新時に再実行すればデータが更新される。

| モード | ソース | 備考 |

| バス路線(補完) | 国土数値情報 バス路線N07・バス停P11 | GTFS未整備事業者の補完 |
| 船(航路) | 国土数値情報 航路データ + OSM ferry route | |
| 空路 | 国土数値情報 空港C28 + 国内線ネットワーク(空港ペア) | 大円航路で描画 |
| 索道 | N02内の索道分類 + OSM aerialway | ロープウェイ・リフト |

スクレイピングは公開オープンデータで不足する部分のみ、robots.txt と利用規約を尊重して行う。

## データフロー

1. `pipeline/sources/*` が各ソースをダウンロード → `data/raw/`
2. `pipeline/build/*` が正規化スキーマ(route/stop/segment + mode + valid_from/valid_to)へ変換
3. tippecanoe で PMTiles 化(路線・駅)。時刻表は路線単位のプリ集計JSONへ
4. web が PMTiles を deck.gl/MapLibre レイヤーとして描画。
   車両アニメは表示中路線の時刻表JSONを遅延ロードし、stop_times間を線形補間

## 主要コンポーネント

- **MapShell**: MapLibre GL(ベース地図+地形) + deck.gl overlay。ピッチ/回転対応
- **ModeLayers**: 鉄道/バス/船/空/索道の PathLayer・ScatterplotLayer。モードトグルUI
- **VehicleAnimator**: 現在時刻(可変速クロック)→ 各tripの位置を補間 → 3Dアイコン描画
- **EraTimeline**: 年スライダー。N05のvalid_from/valid_toでフィルタし当時の網を表示
- **StationPanel**: 駅/停留所タップ → 詳細+発車標(APIオンライン時)+周辺3D建物
- **ApiClient**: openapi.json から型生成。オフライン時はグレースフルに機能縮退

## エラー処理・性能

- API不達・タイル欠損時もローカルデータのみで動作継続(縮退表示)
- モバイルはデバイス性能に応じレイヤー簡略化(車両数上限・ラベル間引き)
- 全国表示時はズームレベルに応じたLOD(tippecanoe自動間引き+主要路線優先)

## 拡張アイディア: 季節軸(2026-07-04 ユーザー提案)

時代スライダー(年)と直交する**季節軸(月/日)**を追加する。日本の交通は季節運行が多い
(スキー場のリフトは冬季のみ、紅葉期限定のロープウェイ・臨時航路、夏季限定の離島航路など)。

データ素材は収集済みソースに既にある:
- 航路 N09: N09_026 に就航期間(例「4月2日〜6月30日」)→ 現状未使用。パースして valid_months 化
- GTFS calendar.txt / calendar_dates.txt: service_id ごとの運行期間・曜日 → 車両アニメと
  路線表示を「選択した日付に運行があるもの」でフィルタ
- OSM aerialway: seasonal / opening_hours タグ → 索道の冬季/夏季運行

UI案: 時代スライダーの横に月セレクタ(または日付ピッカー)。過去年+季節の組み合わせも許す
(例: 1980年の冬)。車両アニメーションはその日のダイヤのみ再生する。

## データ選定ポリシー(2026-07-04 ユーザー指示)

交通系YouTuber・鉄道ファンコミュニティ由来の情報も**データとして存在すれば採用候補にする**。
ただし**出所が保証できないものは除外**する。採用判定の基準:

1. **一次ソースに遡れること** — 公式時刻表・官報・事業者発表・国交省統計等への参照があるもの
2. **構造化データであること** — 動画そのものではなく、コミュニティが整備したデータセット
   (例: Wikipedia/Wikidataの路線・列車愛称記事(出典付き)、OSM、鉄道ファン系のオープンDB)
3. **ライセンスが明示されていること** — CC BY-SA / ODbL / CC0 等
4. 出典不明の個人まとめ・動画内の口頭情報のみのデータは**使わない**

採用したコミュニティ由来データは source フィールドで区別し、クレジット画面に出典を明記する。

## 調査結果: 航空時系列と列車愛称(2026-07-04)

### JAL/ANA 国内線の時系列
「開設年・廃止年」を構造化した一次データは存在しない。採用方針(ポリシー適合順):

1. **ODPT フライト時刻表API**(JAL/ANA、要無料APIキー) — 現行国内線の便名・区間・時刻をJSONで取得。
   公共交通オープンデータ基本ライセンス。→ まず「現在の正確な路線網」をこれで置き換え/補強
2. **国交省 航空輸送統計(e-Stat)** — 路線別運航実績の年次シリーズ。政府統計利用規約。
   複数年の差分から就航・廃止年を推定し、空路の時代スライダー対応に使う
3. **OpenFlights routes.dat** — 2014年凍結スナップショット。当時の路線網として時系列の1点に使える
4. Wikipedia沿革記事(CC BY-SA・出典付き) — 主要路線の開設年の補完キュレーション
5. JAL/ANA公式サイトの直接スクレイピングは利用条件が確認できないため**行わない**

### 列車愛称(あずさ・ソニック・成田エクスプレス等)
構造化APIは存在しない。方針:

1. **Wikipedia個別列車記事の沿革節**(CC BY-SA・出典付き=ポリシー適合) —
   「1966年12月12日: 新宿-松本間に特急『あずさ』新設」形式の年表をキュレーションし、
   `{愛称, 区間(駅名列), 開始年, 終了年, 種別}` の named-trains データセットを作る。
   時代スライダー連動(過去の愛称も出せる)。著名列車から着手し漸次拡大
2. **ODPT JR東日本列車時刻表** — 関東在来線限定だが特急の実時刻が取れる唯一の機械可読源
3. **transit.ls8h.com /stations/{id}/departures** — フェーズ7の発車標で愛称のリアルタイム表示(全国130鉄道フィード)

表示イメージ: 路線ホバーは現状どおり路線名+事業者。named-trains は路線上に愛称バッジ/
専用レイヤーで重ね、時代スライダーで「1988年のあずさ」等も再現する。
